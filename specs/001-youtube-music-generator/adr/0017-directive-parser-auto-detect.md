# ADR-0017: ディレクティブパーサ = 独自実装(自動判別方式)

- **ステータス:** Accepted
- **日付:** 2026-05-25
- **決定者:** @seita
- **タグ:** backend, ml, ux

## 背景

要件4・5 のテンプレ機能(タイトル・説明文・サムネ生成プロンプト)は `{{...}}` 内に2種類のディレクティブが混在する:

1. **データ参照**: 既知の値の差し込み(`{{genre}}` → `"lofi"`)
2. **LLM 生成**: 自由文の指示で LLM が文章生成(`{{この曲の雰囲気を1文で}}`)

要件記法では引用符なしで日本語が直接書かれており、Jinja2 等の既存テンプレ言語では構文エラーになる。
要件の記法を維持しつつ、両者を区別する仕組みが必要。

## 決定

### 構文

- `{{...}}` を唯一のディレクティブ構文とする
- 中身を **自動判別**:
  - 内容が **単一の識別子**(`\w+` のみ、空白なし)→ **変数参照**
  - それ以外(空白を含む・日本語の文章・記号)→ **LLM 生成ディレクティブ**
- 例:
  - `{{genre}}` → 変数 `genre` の値で置換
  - `{{この曲の雰囲気を1文で}}` → LLM が指示文を解釈して生成
  - `{{bpm}}` → 変数 `bpm` の値で置換
- ネストは不可(`{{ {{x}} }}` は禁止)、エスケープは `\{\{` で表記
- 不明な変数参照は **エラー**(運用ミスを早期発見)
- 改善計画 LLM がテンプレを書き換える場合も同じ構文に従う

### LLM 呼び出しの最適化

- 1テンプレ内に複数の LLM 生成ディレクティブがある場合は **1回の LLM 呼び出しで全部展開**
  - 各ディレクティブに ID を振り、JSON で `{ "id1": "...", "id2": "..." }` 形式で返却(構造化出力、ADR は別途)
- LLM に渡すコンテキスト: ジャンル・BPM・キー・サブテーマ・サムネ概要・前後の固定テキスト・他ディレクティブの指示文

### 実装(概略)

```python
import re

DIRECTIVE_RE = re.compile(r"\{\{(.+?)\}\}")
IDENT_RE = re.compile(r"\w+")

def classify(directive_body: str) -> Literal["var", "gen"]:
    return "var" if IDENT_RE.fullmatch(directive_body.strip()) else "gen"
```

### セキュリティ・運用

- テンプレ作成者(本人 + 改善計画 LLM)信頼前提
- 改善計画 LLM がディレクティブ内容を書き換える場合、改善計画スキーマ側でテンプレを構造化フィールドとして保持し、prompt injection が他の生成に波及しない設計にする(ADR は別途)

## 結果

### 良い影響

- 要件の記法そのまま、ユーザー体感が直感的
- 独自パーサは 50〜100 行程度で実装可能、テストも書きやすい
- 1テンプレ内の複数 LLM 呼び出しを1回にバッチ化 → コスト・速度効率良い

### 悪い影響・トレードオフ

- 独自パーサのため Jinja2 のような既存機能(条件分岐・ループ等)は使えない
  - 現時点では不要、必要になれば別途検討
- 自動判別のため、変数名に空白を入れることはできない(`\w+` 制約)
  - 通常の変数命名規則と整合的なので問題なし

### 受容したリスク

- 改善計画 LLM が誤って空白入りの変数名を書くと LLM ディレクティブとして解釈される
  - 対策: 改善計画スキーマ側で変数名を `\w+` に制約する

## 検討した代替案

- **A. 2種類のディレクティブを別記法で区別:** 要件記法から逸脱、テンプレ作成者の認知負荷増。不採用。
- **B. Jinja2 + ヘルパー関数:** 要件記法から逸脱、`{{ gen("...") }}` のクォート必須が要件と合わない。不採用。
- **C. テンプレ全文を LLM に投げて穴埋め:** 出力予測不能、トークン消費増、固定部分まで LLM が書き換えるリスク。不採用。
