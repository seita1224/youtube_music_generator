# ADR-0008: マスターLLM の責務範囲

- **ステータス:** Accepted
- **日付:** 2026-05-25
- **決定者:** @seita
- **タグ:** ml, policy

## 背景

当初要件は「ジャンル選定をマスターLLM に完全委任、Content ID 誤マッチも含めて AI 判断」だったが、グリル(Q4)で以下が判明:

- LLM は Content ID DB にアクセス不可、Content ID 判断材料がゼロ → 実質ランダム
- 「LLM に任せた」がブラックボックスのラベルになり、原因究明を遅らせる
- LLM の責務を明確化し、原理不可能な判断を切り離す必要

## 決定

マスターLLM の責務を以下に **限定** する:

### LLM が担う

- ジャンル選定(プロンプトポリシーの範囲内で創造的に提案)
- ジャンル内サブテーマ展開(ADR-0003、6 サブテーマ)
- ACE-Step のプロンプト生成(BPM・キー・スタイル指定を含む)
- タイトル生成(テンプレ + ディレクティブ展開)
- 説明文生成(テンプレ + ディレクティブ展開)
- サムネ画像生成プロンプトの提案
- 投稿動画のコメント分析(週次)
- 改善計画立案(週次)

### LLM に渡すプロンプトポリシー(必ず守らせる)

- 特定アーティスト名禁止
- 現代のヒット曲名・楽曲タイトル禁止
- 固有名詞(人名・地名・ブランド名)は原則禁止(やむを得ない一般名詞は許容)
- 著作権を意識した中立的なスタイル記述に留める

### LLM が担わない

- **Content ID マッチ判断**(ADR-0005 で AcoustID パイプラインに分離)
- 投稿規模の拡大判断(ADR-0004、人間判断)
- BAN リスクの政策判断(同上)
- システム停止判断(失敗時 Slack 通知のみ、人間判断)

## 結果

### 良い影響

- LLM の責務が明確化、ブラックボックス化を防ぐ
- 原理不可能な判断を期待しないため、運用上の幻想がなくなる
- プロンプトポリシーが明文化され、テスト・改善対象として扱える

### 悪い影響・トレードオフ

- ジャンル選定の自由度はポリシー分だけ狭まる
  - 緩和: ポリシーは ADR / 設定で変更可能、運用しながら調整

### 受容したリスク

- プロンプトポリシーをすり抜ける表現(例: 一般名詞の組合せでアーティスト連想)は残る
  - 対策: AcoustID プレチェック(ADR-0005)で最終防衛線

## 検討した代替案

- **LLM に完全委任(当初要件通り):** Content ID 判断は原理不可能。不採用。
- **LLM 廃止、ルールベースでジャンル選定:** 創造性・適応性が失われる。不採用。
- **責務を文書化しない:** ブラックボックス化が進む。不採用。
