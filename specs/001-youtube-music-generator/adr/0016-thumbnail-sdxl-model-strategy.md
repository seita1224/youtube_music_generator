# ADR-0016: サムネ生成 = Juggernaut XL v10 デフォルト + ジャンル別モデル切替

- **ステータス:** Accepted
- **日付:** 2026-05-25
- **決定者:** @seita
- **タグ:** ml, video, ops

## 背景

ADR-0015 で動画背景に SDXL 生成サムネを置く方針を採用。具体的なモデル選定が必要。
制約:

- VRAM 24GB(ADR-0002 で ACE-Step + SDXL を GPU 用に確保、それぞれ 8〜12GB + 約7GB)
- 商用利用可能なライセンス(マネタイズ前提、ADR-0004)
- ジャンル多様性に対応(lofi、ハードロック、EDM、アニメ系 etc.)
- 1ジャンルあたり 1〜数枚生成、速度より品質
- YouTube サムネ規定: 1280×720 以上、2MB 以下

## 決定

- **デフォルトモデル: Juggernaut XL v10**
  - 写実・シネマティック・肌テクスチャ・自然光・アナトミーがバランス良く、最もオールラウンド
  - lofi/chill/jazz/R&B/ハードロック/シネマティック系の幅広いジャンルでデフォルト適用
  - 商用利用可(CreativeML Open RAIL++-M ベース)
- **ジャンル別の代替モデル**(設定で切替可能):
  - **RealVisXL V5.0** — ヒーリング/アンビエント/ナチュラル系(自然・水・空)
  - **epiCRealism XL** — ドラマチック編集・高品質ポートレート
  - **DreamShaper XL** — EDM/エレクトロニカ/サイバー系(抽象・ネオン・幾何学)
  - **Animagine XL** — アニメ調BGM/ボカロ風
- モデルの **配置と読込**:
  - HuggingFace から事前ダウンロード、ローカル保存(`models/sdxl/<name>/`)
  - `diffusers` ライブラリで読込
  - モデル切替は VRAM の解放/再読込を伴うため、サイクル内ではバッチ化
- ジャンル → モデル + プロンプトの **マッピングは LLM に提案させる**(ADR-0008 の責務範囲)、最終的なモデル選択はテンプレ設定に従う
- スタイル(構図・色味・雰囲気)のデフォルトテンプレを設定可能にする(../requirements.md §機能要件 6.5)
- 出力サイズ: 1280×720 以上(YouTube サムネ規定)、生成後に必要に応じて upscale

## 結果

### 良い影響

- Juggernaut XL がデフォルトで網羅率が高く、運用初期はモデル切替なしで回せる
- ジャンルごとに適切なモデルを選べる柔軟性も確保
- 全モデルが商用利用可能
- VRAM(約 7GB / モデル)が ACE-Step (8〜12GB) と共存可能で、ロード/アンロード切替を最小化できる

### 悪い影響・トレードオフ

- 複数モデルを HuggingFace から取得 → ストレージ消費(各モデル 6〜7GB、合計 30〜40GB)
  - 緩和: 使用頻度の低いモデルは必要時のみダウンロード
- モデル切替が発生する場合はロード時間が増える(数十秒)
  - 緩和: 同一ジャンルのバッチ生成時はモデル維持

### 受容したリスク

- 各モデルの **ライセンス条項の細部** は時期によって変更される可能性
  - 対策: 採用時に LICENSE ファイルを確認し、変更があれば年次レビュー
- LoRA は当面採用せず、必要性が明確になった時点で別 ADR で評価

## 検討した代替案

- **SDXL base 1.0 のみ:** ベースモデルは Juggernaut/RealVis に比べて品質が劣る(特に肌・照明)。不採用。
- **SDXL Turbo / Lightning:** 高速だが品質低、本要件(速度より品質)に合わない。不採用。
- **Flux.1-dev:** 高品質だが非商用ライセンス。不採用。
- **Flux.1-schnell (Apache 2.0):** 商用OK、品質高、ただし VRAM 約12GB で ACE-Step との共存が苦しい。Phase 2 として評価余地あり。当面不採用。
- **LoRA でスタイル切替:** ジャンル別 LoRA の選定・管理コストが追加。当面ベースモデル切替で十分。
