# ADR-0043: 自動運転レベル L0 / L1 / L2 と昇格条件・取り下げ

- **ステータス:** Accepted
- **日付:** 2026-07-25
- **決定者:** @seita
- **タグ:** ops / policy / frontend

## 背景

ADR-0042 で人の判断を公開ゲート 1 点に集約したが、運用が安定したあとも枠ごとに承認を押し続けるのは「定期的に音楽を作り投稿できるシステム」という目的に対して負債になる。一方、初日から全自動にするのは AI 生成物の性質上あきらかに危険である。

旧設計には ADR-0035(dryrun=ON 既定からの段階移行)と 6 項目のチェックリストがあったが、これは dryrun 概念に紐づいており、ADR-0042 の廃止に伴い後継が必要になる。

## 決定

### (1) 自動運転レベルを 3 段階で定義する

| レベル | 公開ゲート | 通知 |
|---|---|---|
| **L0 監督** | 人が承認したものだけ公開する。承認が無ければ公開しない | 完成時に通知 |
| **L1 事後確認** | 自動で公開し、事後に人が確認する。**取り下げ可能** | 公開時に通知(取り下げ導線付き) |
| **L2 全自動** | 自動で公開する | 異常時のみ通知 |

既定は **L0**。レベルはシステム全体に 1 つ持ち、枠ごと・ジャンルごとには持たない。

L1 / L2 では枠は `awaiting_approval` を経由せず、パッケージング完了時にシステムが承認記録を残して `approved` へ進む(ADR-0045)。「誰が承認したか」は監査ログ上で人 / システムを区別する。

### (2) 昇格には実績条件を課す

| 遷移 | 条件 |
|---|---|
| L0 → L1 | 直近 **10 枠が連続で無修正承認**(却下も工程やり直しも無い)、かつその 10 枠で検査の自動不合格が 0 |
| L1 → L2 | L1 での運用が **30 日以上**、かつその期間の取り下げ 0・compliance エラー 0 |

- 条件を満たさないレベルは設定画面で**選択できない**。未達の理由と現在の達成状況(例:「あと 3 枠」)を表示する
- 条件の判定は自動で行い、判定に使った数値を画面に出す
- **降格はいつでも無条件・即時**。L2 → L0 も 1 操作で行える
- レベルの変更は昇格・降格とも監査ログに記録する
- ADR-0044 の compliance 自動停止が発動した場合、**L0 へ自動降格**する

### (3) 取り下げ(L1)の実体

- 取り下げ = **YouTube 動画を private にする**。削除はしない。削除は不可逆で統計も失われるため、事故時でも private 化までとする
- 取り下げた枠は `withdrawn`(終端)。同じ枠での再公開はしない。作り直したい場合は単発枠を追加する(ADR-0041 の例外操作)
- **「24 時間以内」は機能制限ではなく通知上の SLA** とする。公開通知に「あと N 時間」を表示するが、private 化の操作自体は期限後もいつでも可能
- 操作チャネルは admin UI と Slack ボタンの両方に置く。LAN 内 UI だけだと外出中に取り下げられないため

## 結果

### 良い影響

- 「自動化してよい」の根拠が宣言ではなく実績になり、事故時に振り返れる
- 降格の摩擦を 0 にしてあるため、迷ったら下げるという安全側の行動を取りやすい
- L1 が L0 と L2 の間の実用的な踊り場になり、いきなり全自動にする必要がない

### 悪い影響・トレードオフ

- L1 / L2 は Constitution III「投稿という不可逆アクションは人間の一手を挟む」と正面から矛盾する。**憲法の改版を伴う**(Governance の規定どおり、本 ADR + 憲法改版をセットで行う)
- 昇格条件の判定ロジック(無修正承認の連続カウント、期間集計)を実装・テストする必要がある

### 受容したリスク

- L1 で公開された動画は、取り下げても「一度は公開された」事実が残る(視聴・転載の可能性)。private 化までしかできないことを承知のうえで L1 を選ぶ
- 10 枠 / 30 日という数値に統計的根拠は無い。運用実感に基づく初期値であり、事故が起きたら引き上げる

## 検討した代替案

- **レベルを設けず L0 固定:** 目的である運用の自動化に到達しない。不採用
- **ユーザーの宣言だけでレベルを上げられる:** 旧 ADR-0035 のチェックリストが形骸化した経緯と同じ轍。実績条件による解錠を採用
- **枠ごと / ジャンルごとにレベルを設定:** 表現力は上がるが「今どこが自動でどこが手動か」が把握できなくなる。システムに 1 つとする
- **取り下げ = 動画削除:** 不可逆で統計も失う。private 化を採用
