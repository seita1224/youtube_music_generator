# ADR-0049: 成果物の保持・削除ポリシー

- **ステータス:** Accepted
- **日付:** 2026-07-25
- **決定者:** @seita
- **タグ:** ops / backend

## 背景

新設計では成果物が増える方向に働く。工程単位のやり直し(ADR-0046)は旧世代の成果物を生み、見送り・却下・取り下げ(ADR-0045)も成果物を残したまま終端に達する。旧設計の保持方針(ADR-0022 の「楽曲 / サムネは永続、投稿動画は posted 後 N 日で削除」、ADR-0025 の dryrun 状態別 retention)は dryrun 概念の廃止に伴い後継が必要になる。

RTX 3090 単機・ローカルディスク・オフサイトバックアップ無し(ADR-0026)という構成で、無制限に貯めることはできない。

## 決定

| 対象 | 保持 |
|---|---|
| マスター音源(トラック個別 + `mix`) | **永続** |
| サムネイル | **永続** |
| メタデータ(企画 JSON・タイトル・説明文・チャプター・検査結果) | **永続** |
| 監査ログ・枠のタイムライン | **永続** |
| プロンプトの全バージョン | **永続** |
| 公開済みの最終動画(mp4) | 公開確認後 **90 日**で自動削除 |
| やり直しで無効化された旧世代の成果物 | **7 日**保持後に自動削除 |
| `skipped` / `withdrawn` / `rejected_pending` のまま終わった枠の成果物 | **30 日**保持後に自動削除 |

方針の要点:

- **動画ファイルは再生成可能な派生物**であり、公開後は YouTube 側が正本になる。ローカルに置き続ける価値が薄いため最も短命にする
- **音源とサムネは再生成に GPU 時間がかかる一次成果物**なので永続保持する
- **旧世代の 7 日**は「やり直したが前のほうが良かった」に気づくための猶予。7 日を過ぎた旧世代は復元できない
- **終端枠の 30 日**は、見送った成果物を単発枠で再利用する(ADR-0045 (3))ための猶予。30 日を過ぎたら救済できない
- 削除はメタデータを残してファイルのみ削除する。枠詳細は「成果物は保持期間を過ぎたため削除済み」と表示する
- 削除ジョブは日次で実行し、削除件数と解放容量をタイムラインに記録する

バックアップ対象(ADR-0026 のローカル別ディスク)は**永続保持の対象のみ**とする。動画ファイルと旧世代成果物はバックアップしない。

## 結果

### 良い影響

- ディスク使用量の上限が枠数と保持期間から見積もれるようになる
- 「やり直したら前の音源が消えた」という事故が起きない(7 日猶予)

### 悪い影響・トレードオフ

- 90 日を過ぎた公開済み動画をローカルで再確認できない。YouTube から取得するか、音源 + サムネから再合成する必要がある
- 保持期間の異なる 4 系統を管理する分、削除ジョブの実装とテストが必要になる

### 受容したリスク

- 7 日 / 30 日 / 90 日はいずれもディスク実測前の見積もり値。運用開始後に使用量を見て調整する
- 削除は不可逆。バックアップ対象外のものは復元できない

## 検討した代替案

- **すべて永続保持:** 30 分の 1080p 動画は 1 本あたり数百 MB〜1 GB 規模で、日次投稿だと年単位で数百 GB に達する。不採用
- **公開後すぐ動画を削除:** 公開直後の差し替え・確認に困る。90 日を採用
- **旧世代を即時削除:** やり直しの取り消しができない。7 日を採用
