# ADR-0048: 視聴者コメントは読み取り専用で分析に用いる

- **ステータス:** Accepted
- **日付:** 2026-07-25
- **決定者:** @seita
- **タグ:** ops / policy / analytics

## 背景

旧設計はコメント取得と分析を持っていたが、再設計の画面構成でこれを継承するか廃止するかが未決だった。分析画面はコメント由来の定性情報を暗黙の前提にしていた一方、承認を 1 点に集約する方針(ADR-0042)からすると、コメント対応という新しい人の作業を増やすことは方針に反する。

## 決定

- コメントの**取得とセンチメント要約を継承する**。結果を実績スナップショットに含め、企画 LLM の入力とする
- 分析画面に「視聴者の声」セクションを置く(件数・傾向・代表コメント)
- **返信・削除・モデレーションの UI は作らない**。書き込み系 API は使わない
- コメントは ADR-0047 の目的関数には直接入れない。定量判断は視聴時間・維持率で行い、コメントは**企画 LLM への定性的な補助入力**に限る

## 結果

### 良い影響

- 「どの曲調が好まれたか」など、数値に出にくい情報を企画に還元できる
- 読み取り専用に限定したため、人の作業が増えない(ADR-0042 の方針を保てる)

### 悪い影響・トレードオフ

- スパムや悪質コメントが付いても、システムからは何もできない。YouTube Studio で直接対応する
- コメントは母数が小さく偏りやすいため、LLM が過剰に反応する可能性がある。プロンプト側で「参考情報である」と位置づける

### 受容したリスク

- コメント取得は quota を消費する(`commentThreads.list` = 1 unit / call)。公開本数に対して十分小さいが、公開用 quota(ADR-0045)と同じ割当を共有することは認識しておく

## 検討した代替案

- **廃止する:** 分析画面の定性情報が失われ、企画の改善が数値だけに依存する。不採用
- **返信 UI も作る:** 承認 1 点集約の方針に反し、日常作業が増える。不採用
- **コメントを目的関数に組み込む:** センチメントの定量化が恣意的になり、判断根拠として説明できない。不採用
