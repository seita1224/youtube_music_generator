# ADR-0002: マスターLLM はクラウドAPI 前提、ローカルへの切替層は維持

- **ステータス:** Accepted
- **日付:** 2026-05-25
- **決定者:** @seita
- **タグ:** ml, backend, infra

## 背景

マスターLLM はジャンル選択・改善計画立案・説明文/タイトル生成・コメント分析の中核。
当初は「ローカルLLM限定で運用、将来クラウドAPIへ切替可能」としていたが、グリル(Q6)で以下が判明:

- RTX 3090 (24GB) を ACE-Step (8〜12GB) + SDXL (10〜12GB) で共用すると、ローカルLLM (13B Q4 ≒ 8〜10GB) を同時常駐できない
- ロード/アンロード切替が発生し、1サイクルあたり数十分のオーバーヘッド
- 1日1〜2本の規模ではクラウドLLM の呼出コストは月数百円〜千円程度(ジャンル選定 + 説明文生成のみ)
- クラウドAPI に逃がせば VRAM は音楽 + 画像専用に確保できる

## 決定

- **デフォルト = クラウドAPI**(初期は Claude Haiku または GPT-4o-mini 等の安価モデル)
- **抽象化層**(`LLMProvider` インターフェース)を実装し、設定で以下を切替可能にする
  - Anthropic API / OpenAI 互換 API / Ollama(ローカル)
- 切替は環境変数 + 管理UI から可能
- プロンプト・コンテキスト窓・トークン使用量は provider 非依存に管理

## 結果

### 良い影響

- VRAM 24GB を音楽 + 画像の用途に集中できる
- モデル切替が「設定変更のみ」で完結、コード変更不要
- 上位モデル(Claude/GPT)の品質に最初から乗れる

### 悪い影響・トレードオフ

- クラウドAPI 月額コスト(規模が増えるほど増加)
- API 障害・レートリミット時の縮退設計が必要
  - 緩和: ジョブは「失敗時 Slack 通知のみ、自動リトライなし」方針で運用 (../requirements.md)

### 受容したリスク

- 外部依存が増えるが、要件「失敗時は人間判断」と整合
- 将来コスト最適化のため、運用後にローカル切替も評価可能

## 検討した代替案

- **ローカルLLM限定:** VRAM 圧迫 + GPU時間予算オーバーリスク。不採用。
- **クラウド固定:** 抽象化層を作らず Anthropic SDK を直接呼ぶ。将来切替が困難になるため不採用。
- **両方同時起動:** 24GB に収まらない。不採用。
